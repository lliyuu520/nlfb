## 1. 背景与目标

### 1.1 为什么做

- 现状短板：单局内成长固定（wlevel 1→4 + 导弹 0→3），三局之间体验差异小；关卡制内容消耗快；操作天花板即游戏天花板。
- 肉鸽层直接解决：把"每局的随机性"从随机掉落升级为"随机构筑"，这是留存和单局时长的核心杠杆，也是界面新闻品类复盘里 STG 大众路线的"标准答案"。
- 与现有系统边际成本最低：掉落保底、`UPGRADES` 定义模式、`hitStop` 冻结、pause 触摸热区、`UI.drawNeonPanel` 面板、CDN 图标管线全部现成。

### 1.2 成功指标（上线后 2 周看微信"数据助手"，不自建埋点）

| 指标 | 基线（0.0.x） | 目标（0.1.0） |
|---|---|---|
| 次日留存 | 待记录 | ≥ 15%（IAA 休闲及格线） |
| 人均单次使用时长 | 待记录 | +30% 以上 |
| 人均广告展示次数 | 待记录 | +1 次/DAU（来自刷新广告 + 复活价值提升） |

> M1 前先确认 0.0.x 的基线数值已截图留存，否则无法对比。

## 2. 设计定位

### 2.1 商业定位

IAA（激励视频）为主的中轻度肉鸽 STG。对标路线：《九重试炼》《机甲变变变》（纯广告变现的肉鸽割草），而非《擎天战机》的重养成内购。差异化占位：**雷电正统街机味（道中掉落/判定点/炸弹）+ 轻构筑 + 好友/世界双榜**。

### 2.2 暂不做清单（YAGNI，写了就是欠债）

- ❌ 僚机实体（绕飞的跟随机）：粒子+弹道生成已可表达"火力膨胀"，实体僚机是新的实体管理系统
- ❌ 战机属性差异：SHIPS 现为纯涂装，动它会牵连皮肤定价与 owned 存档，0.2.x 再议
- ❌ 局外天赋树 / 抽卡 / 内购：金币强化（drop/power）已是局外层，够用
- ❌ 自适应难度：先用静态曲线调系数，数据证明失配再做
- ❌ 武器替换型构筑（"散弹枪替换主炮"类）：与雷电式 wlevel 体系打架，MVP 只做正交增强
- ❌ 牌图标美术：M1/M2 用"字母+颜色色块"程序绘制（复用道具 letter 风格），M3 视留存决定是否投入 AI 生图

## 3. 玩法设计

### 3.1 核心循环

```
拖动移动·自动射击 → 击杀得经验 → 经验条满 → 全屏冻结·三选一 → 本局构筑变强
        ↓                                                      ↓
  道中掉落(雷电味保留)                                更深的关 → 死亡/通关结算 → 金币→局外强化
```

### 3.2 经验与升级

- **经验来源**：击杀敌人 `gainExp = round(e.score / 10)`。grunt 10 / weaver 12 / diver 14 / turret 16 / 小 Boss 60 / Boss 150（Boss 经验在 `nextStage()` 后首帧结算，不打断通关动画）。
- **升级曲线**（增量需求，累计见附录 B）：`[18, 40, 70, 108, 155, 210, 275, 350, 435, 530]`，共 10 级。
  - 第 1 关（35s Boss，约 330 经验）升 3~4 次 → 新手关就能体验构筑爽点；
  - 一局 4~5 关合计 13~15 次 → 构筑感成立但不打断躲弹幕节奏；
  - 满 10 级后经验溢出自动转为 `+500 分`。
- **触发交互**：`state='levelup'`，世界冻结（弹幕、刷怪、计时全停，BGM 不停），中央面板三张牌纵向排列，点选后 `p.inv = max(p.inv, 0.5)` 防恢复瞬间被弹幕瞬杀。
- **双击暂停与选牌冲突**：levelup 态下双击检测不生效（复用 pause 态的触摸分支前置规则）。
- **切后台**：`wx.onHide` 现仅对 playing 生效，levelup 世界本来就冻结，保持现状不改。

|---|---|---|---|---|---|---|

### 3.4 与雷电式掉落的职责分离（不许越界）

| 系统 | 职责 | 保持不变 |
|---|---|---|
| 道中掉落 R/B/Y/P/M/S | 武器种类与等级（换枪、修血）、炸弹补给、小分 | 掉率、保底、异色平切规则全部不动 |
| 肉鸽三选一 | 火力倍率、弹道结构、生存、经济加成 | 不提供"换武器"选项，不直接给 R/B 道具 |

原则：掉落是"街机反馈"，三选一是"策略层"。三选一永远不产生 `kind:'w'/'m'` 的拾取效果，避免架空掉落系统。

### 3.5 流派（设计自检用，不做成系统）

- **弹幕海**：wing×3 + big×3 + rapid×4 → 弹幕密度质变
- **穿晶线**：laser 武器 + laser×3 + dmg×5 + crit×3 → 单线高穿透
- **蜂巢流**：homing 导弹 + missile×3 + 超大当量 → 挂机式副火力
- **铁壁流**：armor×2 + shield×3 + fix + mini + invuln → 低容错变高容错
- 自检标准：任意两张牌之间不冲突；任一流派 10 级满配 DPS 落在基准的 2.5~4 倍（附录 A）。

### 3.6 难度曲线调整

玩家满构筑 DPS ≈ 基准 3~4 倍，现有曲线会失配。分两步走：

- M1：完全不动，先跑手感（前 2 关失配不明显）；
- M2：按建议系数上调（只改常量）：
  - Boss HP：`260+stage*140` → `260+stage*240`，第 1 关仍单独 300；
  - 敌人 HP：grunt/weaver/diver/turret 基础值 ×(1+0.25·(stage−1))；
  - 敌弹速度：stage≥3 后 +10%/关（封顶 +40%）。

### 3.7 广告点位（克制原则：全部可选，不强制）

| 点位 | 状态 | 说明 |
|---|---|---|
| 看广告复活 | 已有 | 保留；构筑越深复活价值越高（核心协同） |
| 结算金币翻倍 | 已有 | 保留 |
| 看广告领金币 | 已有 | 保留 |
| **三选一刷新**（新增） | 每局限 1 次 | 面板角落小按钮，走 `ads.js` 现有封装；观看后 3 张牌重抽。不做"看广告直接得稀有牌"（破坏抽取体验） |

### 3.8 排行榜口径（提前定调）

构筑会让分数膨胀 2~4 倍，世界榜历史记录会被肉鸽分碾压。决策：

- **0.1.0：接受膨胀，不拆榜**。理由：个人项目初期榜单规模小，且"刷高分"本身是新版本的传播点；
- hi 分存档 key（`nulei_hi`）不动，版本更新说明里注明"构筑版本分数不与旧版直接对比"；
- 若上线后榜内出现"断档刷分"投诉/生态问题，0.2.x 拆"经典榜（关构筑）/ 构筑榜"，接口端加 `mode` 字段（`rank.js` 与 nulei-server 两端同步改，动契约需单独评审）。

## 4. 技术方案

### 4.1 总原则

- **不新增 js 文件**：牌池定义表放 `main.js` 的 `UPGRADES` 旁（同一经济区），与项目"所有玩法逻辑集中在 main.js、js/ 下只放组件库（ui/sfx/cdn/ads/settings/rank/loop）"的既有结构一致。
- 最小侵入：所有接入点都是在现有函数里"加一项乘数 / 加一发弹 / 前置一个判断"，不重写现有函数。

### 4.2 数据结构与状态机

```js
// —— 牌池定义（main.js，UPGRADES 旁）——
const BUFFS = [
  {id:'dmg',  name:'弹头强化', rar:'N', max:5, desc:'全伤害 +25%'},
  // ...同 §3.3 表，数值公式不进定义表，散在接入点（与 UPGRADES.val 模式一致的可收进 val:lv=>…）
];
// —— 局内状态（不入存档）——
player.buffs = {};          // {dmg:2, rapid:1, ...} 计数
player.shield = 0; player.shieldT = 0;   // 护盾专用
player.maxLives = 3;
let exp=0, expLv=1, lvQueue=0;           // 经验与待选牌数
const EXP_NEED=[18,40,70,108,155,210,275,350,435,530];
const buffLv=id=>player.buffs[id]||0;
```

- **状态机**：`title / playing / pause / levelup / over / clear`。`levelup` 视同 pause 处理：update 直接早退（`if(state!=='playing')return` 已天然覆盖）；触摸分支按 pause 的模式（main.js:249）加一段。
- **选牌流程**：`gainExp()` 中 `exp>=EXP_NEED[expLv-1]` → `lvQueue++`；每帧 update 末尾检查 `if(state==='playing'&&lvQueue>0)` → 抽 3 张、`state='levelup'`。多级连升时逐次选牌（选完一张 lvQueue-- 再判断）。
- **抽牌函数** `roll3()`：过滤满级牌 → 按 N:R 权重抽 3 张去重 → 不足用 `reserve` 补位。

### 4.3 接入点映射（改动最集中的 6 处）

| 现有代码位置 | 改法 |
|---|---|
| `update()` :476 `dmgMul` | 改为综合倍率：`UPGRADES.power × (1+0.25·lv('dmg'))`，命中处经 `dmgOf(b)` 统一结算 |
| 子弹命中 :511-512 两处 `hit.hp-=b.dmg*dmgMul` | 收敛为 `hit.hp-=dmgOf(b)`；`dmgOf` 内处理暴击 roll（新增 ~8 行函数） |
| `firePlayer()` :384-401 | std 末尾按 `lv('wing')` push 侧翼弹、`lv('rear')` push 背射弹；laser 分支乘 `lv('laser')` 系数；`fireT` 周期在 :489 除以速射系数 |
| `fireMissile()` :402 | 发数 `mlevel+1` → `mlevel+1+lv('missile')` |
| `hurtPlayer()` :583-588 | 前置护盾判断（消耗 shield→return）；`wlevel--` 加 `lv('fix')` 豁免；`p.inv` 加相位涂层；`over` 牌受击时 `buffs.over=0` |
| `startRun()` :307-311 | 初始化 `buffs/shield/maxLives/exp/expLv/lvQueue`；`lives` 取 `maxLives` |

其余（magnet 拾取半径、drop 叠乘、greed 得分乘、bombl、supply）都是单点小改，随做随加。

### 4.4 UI（全部程序绘制，零新素材）

- **经验条**：屏幕最顶端全宽 3px 荧光条（`HUD_TOP` 之上、刘海 inset 之下），填充色随等级微调；升级瞬间白闪一帧。每帧仅多 1 次 `fillRect`，无 fillText。
- **三选一面板**：复用 `UI.drawNeonPanel(ctx, W/2-150, H*0.22, 300, 340, '升 级 · 三 选 一', 稀有度色)`；三张牌卡纵向排列（每卡 280×88：左侧程序绘制图标块 40×40（字母+底色，复用道具 letter 风格）、右侧名称 + 一行描述）；卡间触摸热区 `inRect` 判断（复用 pause 模式）。
- **刷新按钮**：面板底部一行小字按钮 `▶ 看广告 换一批（剩 1 次）`，已用则置灰文案。
- **HUD 牌列表**：不画。构筑状态通过火力观感自解释，省 fillText 与视线遮挡（lszj/AGENTS.md 红线：HUD 遮挡视线是重点检查项）。

### 4.5 性能约束（lszj/AGENTS.md 红线）

- levelup 面板为一次性绘制（每帧重绘但元素少：1 面板 + 3 卡 + ~10 次 fillText），且此时弹幕循环已早退，帧预算反而宽松；
- `dmgOf` 是热点路径（每颗子弹每帧命中判定），内部不做对象分配，纯数值计算；
- 经验条、护盾图标各 1 次 drawRect，可忽略。

### 4.6 存档兼容

- buffs/exp 均为局内变量，**不入 wx.storage**；
- 广告刷新次数为局内变量（每局限 1 次），**不新增存档 key**；
- `nulei_hi / nulei_coins / nulei_up / nulei_owned / nulei_ship / nulei_bg` 全部不动，老玩家升级无感。

## 附录 A：DPS 基准与平衡锚点

基准（0.0.2，无构筑，局外 power=0）：

- std 满级（wlevel4）：5 发 ×1 伤害 / 0.09s ≈ **55 DPS**；laser 满级：2.5 伤 / 0.11s ≈ 23 DPS 单体（穿透 ×N 群体）；
- 导弹 homing 满级：4 发 ×3 / 0.5s = 24 DPS；
- 第 3 关 Boss HP≈680 → 基准击杀约 12s（单体 std）。

构筑后预算：每级牌平均 +12% 有效输出 ×10 级 ≈ 3.1×；满配流派（弹幕海/穿晶线）应落在 **170~220 DPS**。M2 难度上调即按此反推（§3.6 系数使第 3 关 Boss≈1500~1700 HP，混搭流击杀 20~40s）。
